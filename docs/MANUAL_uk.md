# FlexiSoft Runtime — посібник з інтеграції та сервісу

Цей посібник доповнює README і описує практичне налаштування FlexiSoft Runtime. Він призначений насамперед для інтеграції в наявну машину, редагування конфігурації, підготовки текстів повідомлень і базової діагностики.

FlexiSoft Runtime — це допоміжна програма для оператора та сервісу. Вона не є частиною функції безпеки машини. Безпечне оцінювання та reset логіки безпеки завжди мають забезпечуватися проєктом Flexi Soft і проводкою машини.

---

## 1. Принцип

Runtime періодично читає status bits з Flexi Soft через RK512. З цих бітів він оцінює контрольовані канали та відповідно до їхнього стану показує повідомлення оператору.

Якщо оператор після перевірки підтверджує reset, runtime записує налаштований RS-232 command bit. Проєкт Flexi Soft створює з цього біта короткий імпульс reset.

Базовий потік:

```text
FlexiSoftRuntime.exe
    -> RK512
    -> RS-232 або TCP/RS-232 перетворювач
    -> Flexi Soft CPU
    -> логіка проєкту
    -> reset-реле / вихід
```

## 2. Важливі файли

| Файл / папка | Значення |
| --- | --- |
| `conf/config.json` | Головна конфігурація runtime: комунікація, канали, виходи, тексти повідомлень, журналювання. |
| `conf/languages.json` | Переклади інтерфейсу, назви мов і додаткові шрифти. |
| `conf/runtime_state.json` | Останні runtime-вибори користувача, наприклад остання вибрана мова. |
| `docs/` | Локалізована документація. |
| `docs/assets/` | Зображення, використані в документації. |
| `fonts/` | Додаткові шрифти. |
| `flexi_runtime.log` | Сервісний журнал самої програми. |

Метадані вікна About не зберігаються в окремому runtime-файлі. Назва продукту, версія, локалізовані описи (EN/CZ/UK/FR/DE), дата build, тип build, toolset і цільова система під час build компілюються в `FlexiSoftRuntime.exe` з `src/about.h`. Тому їх зміна потребує нового build; перезавантаження конфігурації не змінює дані About.

Для практичного ручного розгортання окремий файл метаданих версії не потрібен. Базова структура:

```text
FlexiSoftRuntime.exe
FlexiSoftMdReader.exe          # рекомендований переглядач документації
conf/
  config.json
  languages.json
  runtime_state.json          # необов’язковий; runtime створює/оновлює його за потреби
docs/
fonts/                        # необов’язково; потрібно лише для налаштованих файлів шрифтів
```

Звичайний оператор не редагує ці файли.

## 3. Конфігурація `conf/config.json`

`conf/config.json` — це головна конфігурація машини. Рекомендований формат — UTF-8.

Рядки JSON можна записувати безпосередньо в UTF-8 або за допомогою escape `\uXXXX`. Підтримуються коректні UTF-16 surrogate pairs. Для конфігураційних і мовних файлів бажаним залишається прямий запис UTF-8.

Базова структура:

```json
{
  "language": "",
  "transport": "",
  "serial": {},
  "network": {},
  "rk512": {},
  "poll": {},
  "inputs": [],
  "ui": {},
  "logging": {},
  "debug": {}
}
```

### 3.1 `language`

```json
"language": "cz"
```

Мова програми за замовчуванням. Використовується при першому запуску або якщо runtime-мова не збережена.

Рекомендації:

- базовий fallback — `en`,
- чеська використовує `cz`,
- українська використовує `uk`,
- інші мови можна додати в `conf/languages.json`.

Зміна мови під час роботи не перезаписує `conf/config.json`.

---

### 3.2 `transport`

```json
"transport": "network"
```

Визначає спосіб комунікації.

| Значення | Опис |
| --- | --- |
| `serial` | Прямий COM/RS-232 порт. |
| `network` | Мережевий транспорт через TCP або UDP. |

Для інтеграції в машинний OP/PC зазвичай підходить режим `network` з Ethernet/RS-232 перетворювачем.

## 4. Послідовна комунікація `serial`

Секція `serial` використовується при:

```json
"transport": "serial"
```

Приклад:

```json
"serial": {
  "port": "COM5",
  "baud": 115200,
  "data_bits": 8,
  "parity": "N",
  "stop_bits": 1,
  "timeout_ms": 2500
}
```

| Параметр | Опис |
| --- | --- |
| `port` | Назва COM-порту, наприклад `COM4` або `COM5`. |
| `baud` | Швидкість послідовної лінії. |
| `data_bits` | Кількість data bits. Зазвичай `8`. |
| `parity` | Парність. Зазвичай `N`. |
| `stop_bits` | Кількість stop bits. Зазвичай `1`. |
| `timeout_ms` | Timeout для читання та запису по послідовній лінії. |

Для Flexi Soft у цьому проєкті зазвичай використовується:

```text
115200 8N1
```

## 5. Мережева комунікація `network`

Секція `network` використовується при:

```json
"transport": "network"
```

Приклад:

```json
"network": {
  "mode": "tcp_client",
  "host": "192.168.0.7",
  "port": 4001,
  "bind_host": "0.0.0.0",
  "bind_port": 0,
  "connect_timeout_ms": 3000,
  "timeout_ms": 1500
}
```

| Параметр | Опис |
| --- | --- |
| `mode` | Режим мережевого транспорту. |
| `host` | IP-адреса або hostname перетворювача. |
| `port` | TCP/UDP порт перетворювача. |
| `bind_host` | Локальна адреса для UDP bind. У режимі TCP client зазвичай не потребує зміни. |
| `bind_port` | Локальний порт для UDP bind. `0` означає автоматично. |
| `connect_timeout_ms` | Timeout для встановлення TCP-з’єднання. |
| `timeout_ms` | Timeout для читання відповіді. |

Підтримувані значення `mode`:

| Значення | Опис |
| --- | --- |
| `tcp_client` | Runtime підключається як TCP-клієнт до Ethernet/RS-232 перетворювача. Рекомендований режим. |
| `udp` | UDP-режим. Використовувати лише якщо це відповідає конкретному перетворювачу і протестовано. |

Практичне впровадження на машині:

```text
OP/PC машини з runtime
    -> наявний Ethernet машини
    -> Ethernet/RS-232 перетворювач
    -> RS-232 Flexi Soft CPU
```

Так не потрібно тягнути окрему довгу RS-232 трасу між OP машини та шафою керування.

## 6. RK512 `rk512`

Приклад:

```json
"rk512": {
  "device_local": "0x4F",
  "device_reply": "0x4D",
  "token_hex": "0F 0F 46 4C 58 54 30 31"
}
```

| Параметр | Опис |
| --- | --- |
| `device_local` | Локальна RK512-адреса runtime-програми. |
| `device_reply` | Очікувана RK512-адреса відповіді з Flexi Soft. |
| `token_hex` | Token, який використовується перед записом command. |

У конфігурації використовуй `token_hex`.

Значення мають відповідати перевіреній RK512-комунікації конкретного проєкту.

## 7. Polling `poll`

Приклад:

```json
"poll": {
  "period_ms": 1000,
  "read_block": "0x76",
  "read_size": 54
}
```

| Параметр | Опис |
| --- | --- |
| `period_ms` | Період читання status block. |
| `read_block` | RK512-блок, з якого читаються стани. |
| `read_size` | Кількість байтів для читання. |

З прочитаного блоку runtime оцінює канали за `status_byte`, `on_bit` і `ok_bit`.

## 8. Канали `inputs`

Runtime підтримує до чотирьох каналів. Кожен канал є елементом масиву `inputs`.

Приклад:

```json
{
  "enabled": true,
  "name": "Саркофаг ліва сторона",
  "status_byte": 0,
  "on_bit": 0,
  "ok_bit": 1,
  "alert_text_uk": "Перевір, чи ліва сторона саркофага повністю закрита.",
  "output": {
    "block": "0x42",
    "byte": 0,
    "bit": 0,
    "pulse_ms": 1000
  },
  "repeat_fault": {
    "count": 3,
    "window_ms": 30000,
    "ignore_after_command_ms": 1500,
    "text_uk": "Помилка повторно повертається. Перевір лівий кожух і датчик."
  }
}
```

### 8.1 Базові параметри каналу

| Параметр | Опис |
| --- | --- |
| `enabled` | Увімкнення/вимкнення каналу. Вимкнений канал не контролюється і не показує повідомлення. |
| `name` | Назва каналу, що показується у tray-меню та повідомленнях. |
| `status_byte` | Індекс байта в прочитаному status block. |
| `on_bit` | Інформаційний ON/OFF bit каналу. |
| `ok_bit` | Bit, за яким runtime вирішує, чи канал у порядку. |
| `alert_text_<мова>` | Текст звичайного повідомлення для відповідної мови. |

Старий ключ `alert_text` може бути fallback, але рекомендовані мовні ключі:

```text
alert_text_en
alert_text_cz
alert_text_uk
alert_text_fr
alert_text_de
```

Якщо активна мова не має тексту, runtime використовує англійську або fallback-текст.

### 8.2 Вихідний command `output`

```json
"output": {
  "block": "0x42",
  "byte": 0,
  "bit": 0,
  "pulse_ms": 1000
}
```

| Параметр | Опис |
| --- | --- |
| `block` | RK512-блок для запису command. |
| `byte` | Byte у даних, що записуються. |
| `bit` | Bit у цьому byte. |
| `pulse_ms` | Час, протягом якого runtime утримує command bit. |

Під час command runtime встановлює bit, чекає `pulse_ms`, а потім вимикає bit.

Важливо: навіть якщо runtime утримує bit лише обмежений час, короткий reset-імпульс має бути також створений у логіці Flexi Soft. Це запобігає постійному ефекту при втраті комунікації або зупинці програми.

## 9. Повторне повідомлення `repeat_fault`

Repeat fault обробляє ситуацію, коли та сама помилка повторно повертається після reset-імпульсу.

Приклад:

```json
"repeat_fault": {
  "count": 3,
  "window_ms": 30000,
  "ignore_after_command_ms": 1500,
  "text_uk": "Перевір правильне закриття кожуха."
}
```

| Параметр | Опис |
| --- | --- |
| `count` | Скільки разів помилка може повернутися в активному вікні, перш ніж виникне повторне повідомлення. Мінімум `1`. |
| `window_ms` | Часове вікно для підрахунку повторних повернень помилки. Мінімум `1000 ms`. |
| `ignore_after_command_ms` | Захисний час після reset command. У цей час runtime ігнорує перехідний стан входів, спричинений апаратним reset через реле. Від’ємні значення трактуються як `0`. |
| `text_<мова>` | Текст повторного повідомлення для відповідної мови. |

Рекомендовані мовні ключі:

```text
text_en
text_cz
text_uk
text_fr
text_de
```

### 9.1 Як рахується повторення

Після підтвердження reset runtime надсилає reset command і запускає захисний час `ignore_after_command_ms`.

Цей час не призначений головним чином для того, щоб «не повідомляти повернення тієї самої помилки». Його справжня мета — відфільтрувати перехідний стан входів під час апаратного reset.

Під час reset контрольовані вхідні канали на короткий час розмикаються через реле. У цьому стані обидва канали входу можуть бути OFF, і Flexi Soft знову починає відлік свого часу синхронності каналів. З погляду runtime вхід може на мить виглядати як OK, хоча це лише перехідний стан, викликаний reset.

Якби runtime оцінив цей короткий стан як справжній OK, він би помилково скинув логіку повторного повідомлення. Тому протягом `ignore_after_command_ms` перехідний стан не впливає на repeat-логіку.

Під час `ignore_after_command_ms` runtime:

- не вважає короткий OK стан справжнім виправленням входу,
- не скидає лічильник повторень,
- не зараховує перехідний стан як нове повернення помилки,
- не відкриває нове повідомлення за перехідним станом.

Після завершення `ignore_after_command_ms` runtime знову оцінює реальний стан каналу:

- якщо канал усе ще в помилці, лічильник повторень збільшується,
- якщо канал після захисного часу справді в порядку, лічильник повторень скидається,
- якщо лічильник досягне `count`, показується повторне повідомлення.

Час очікування оператора перед підтвердженням рахується в `window_ms`. Тривалість command, тривалість імпульсу і захисний час `ignore_after_command_ms` не входять в активне вікно.

### 9.2 Активні помилки та repeat limit

Лічильники повторень ведуться окремо для кожного контрольованого каналу. Внутрішньо розділені поточні активні помилки (`errorMask`) і канали, які вже досягли repeat limit (`repeatMask`). Тому repeat alert може показувати всі поточні активні помилки, а коригувальний repeat-текст — лише для каналів, що входять до `repeatMask`.

## 11. Журналювання `logging`

Приклад:

```json
"logging": {
  "enabled": true,

  "newest_first": true,

```

| Параметр | Опис |


## 13. Runtime-стан `conf/runtime_state.json`

`conf/runtime_state.json` зберігає останній runtime-вибір користувача, наразі головно мову.

Приклад:

```json
{
  "language": "cz"
}
```

Якщо файл відсутній, використовується мова з `conf/config.json`. Якщо файл пошкоджений, runtime записує warning у журнал і використовує мову з `conf/config.json`.

Зміна мови під час роботи не перезаписує `conf/config.json`.

Якщо запис `runtime_state.json` не вдається, runtime лише записує warning у журнал. Уже вибрана мова UI залишається активною і не повертається назад.

## 14. Переклади `conf/languages.json`

`conf/languages.json` містить переклади UI та додаткові налаштування шрифту.

Базова структура:

```json
{
  "languages": {
    "en": {
      "name": "",
      "font_face": "",
      "font_file": "",
      "strings": {}
    }
  }
}
```

### 14.1 `languages`

Об’єкт `languages` містить окремі мови. Ключ мови одночасно є її кодом, наприклад:

```text
en
cz
uk
fr
de
```

### 14.2 Параметри мови

| Параметр | Опис |
| --- | --- |
| `name` | Назва мови, що показується в tray-меню. |
| `font_face` | Назва системного шрифту або font face. |
| `font_file` | Додатковий файл шрифту, відносно папки програми. |
| `strings` | Ключі перекладу UI. |

Якщо `font_file` існує і може бути завантажений, runtime використовує цей шрифт. Інакше використовується fallback-шрифт. Це важливо особливо для мов, для яких на старих Windows може не бути відповідного системного шрифту.

### 14.3 Правила fallback для перекладів

- Англійська (`en`) є базовим fallback.
- Якщо активна мова не містить певного тексту, використовується англійський текст.
- Якщо тексту немає навіть англійською, показується назва ключа.
- Відсутній або порожній `conf/languages.json` runtime може замінити базовим англійським шаблоном.

### 14.4 Важливі ключі перекладу

#### Tray-меню

| Ключ | Опис |
| --- | --- |
| `tray.title` | Заголовок tray-меню. |
| `tray.reload_config` | Пункт для перезавантаження конфігурації. |
| `tray.reconnect` | Пункт для reconnect комунікації. |
| `tray.about` | Пункт About. |
| `tray.exit` | Завершення програми. |
| `tray.language` | Підменю мов. |
| `tray.send_command` | Текст ручного command; підтримує token `{channel}`. |

#### Тексти стану

| Ключ | Опис |
| --- | --- |
| `status.ok` | Стан OK. |
| `status.error` | Стан помилки. |

Документація зазвичай відкривається зовнішнім `FlexiSoftMdReader.exe` (v1.0.1 в актуальному пакеті Runtime). Runtime передає Reader вибраний документ і фактичний шрифт UI. Reader v1.0.1 містить сумісну обробку для старого IE engine, який використовується у Windows XP. Якщо Reader неможливо використати, runtime переходить до Notepad, а потім до ShellExecute. Reader підтримує підмножину Markdown, що використовується в наданій документації, включно із зображеннями з `docs/assets/`.

## 17. Налаштування у Flexi Soft Designer

### 17.1 RS-232 routing

У проєкті має бути увімкнено:

```text
Увімкнути RS-232 routing для CPU
```

![Налаштування RS-232 routing для CPU](assets/flexisoft_designer_rs232_routing.png)

### 17.2 Короткий імпульс у логіці CPU

Runtime записує command bit, але сам короткий імпульс має бути створений також у проєкті Flexi Soft.

Рекомендований принцип:

```text
RS-232 bit -> виявлення фронту -> таймер / короткий імпульс -> reset-реле або reset-вихід
```

![Приклад reset-реле з RS-232 бітів](assets/flexisoft_designer_rs232_reset_relays.png)

Причина: при втраті комунікації або зупинці runtime контрольовані входи не повинні залишитися постійно відключеними, а reset-сигнал не повинен залишитися постійно активним.

## 18. Перезавантаження конфігурації

Конфігурацію можна перезавантажити з tray-меню.

Знову завантажуються:

- `conf/config.json`,
- `conf/languages.json`,
- `conf/runtime_state.json`.

Метадані About вбудовані в EXE і не змінюються при перезавантаженні конфігурації.

Якщо повідомлення відкрите, runtime його закриє. Якщо помилка все ще триває, він покаже нове повідомлення за актуальною конфігурацією та актуальними текстами.

Reconnect використовує той самий modeless-alert flow: старе повідомлення закривається перед reconnect, а якщо помилка після відновлення комунікації все ще присутня, показується нове актуальне повідомлення.

## 19. Tray-іконка і tray-меню

Tray-іконка показує загальний стан комунікації та каналів:

| Стан іконки | Опис |
| --- | --- |
| Зелена | Комунікація справна, і жоден контрольований канал не в помилці. |
| Червона | Комунікація справна, але принаймні один контрольований канал у помилці. |
| Жовта / нейтральна | Запуск, reconnect або очікування підтвердження стану. |
| Сіра / помилка комунікації | Runtime не має дійсного з’єднання з Flexi Soft CPU. |

Tray-меню показує стан увімкнених каналів CH1–CH4. Для кожного каналу видно його назву та стани ON/OFF і OK/ПОМИЛКА.

Ручні command доступні лише при дійсній комунікації з CPU.

## 20. Журналювання та діагностика

Журнал є сервісним журналом програми, а не виробничим чи безпековим журналом машини.

Журналюється, наприклад:

- запуск програми,
- завантаження конфігурації,
- відкриття транспорту,
- помилка комунікації,
- відновлення комунікації,
- показ повідомлення,
- command ON/OFF,
- збій command,
- повторне повідомлення,
- reconnect,
- shutdown.

При тривалій однаковій помилці комунікації runtime обмежує переповнення журналу. Та сама помилка не записується в кожному циклі, якщо не змінюється стан або текст помилки.

## 21. Усунення несправностей

### Runtime не підключається

Перевір:

- тип транспорту,
- IP-адресу та порт перетворювача,
- COM-порт,
- послідовні параметри,
- проводку,
- живлення перетворювача,
- RS-232 routing у проєкті Flexi Soft,
- RK512-адреси.

### Перетворювач доступний, але Flexi Soft не відповідає

Перевір:

- чи Flexi Soft CPU у RUN,
- чи правильно підключений RS-232 інтерфейс,
- чи відповідають RK512-налаштування,
- чи відповідають read block і size,
- чи проєкт містить потрібні сигнали.

### Ручний command неактивний

Runtime не має дійсної комунікації з Flexi Soft CPU. Спочатку віднови комунікацію або перевір перетворювач.

### Повідомлення повертається після reset

Після завершення захисного часу контрольований вхід усе ще в помилці. Перевір кожух/саркофаг, датчики та проводку.

### Повторне повідомлення

Помилка повторно повертається після reset. Оператор не повинен продовжувати підтвердження без фізичної перевірки. Потрібно перевірити кожух, датчики, проводку або логіку безпеки.

### Command не вдався

Не вдалося записати або вимкнути command bit. Перевір комунікацію, RK512 write block, token і RS-232 routing.

## 22. Контрольний список перед передачею

Перед передачею перевір:

- RS-232 routing для CPU увімкнено.
- RS-232 command-біти підключені в логіці Flexi Soft.
- Reset-імпульс створюється у Flexi Soft як короткий імпульс.
- Комунікація відповідає налаштуванням у `config.json`.
- Read block і size відповідають проєкту.
- Status bytes і bits відповідають проєкту.
- Output command bits відповідають проєкту.
- Тексти повідомлень зрозумілі оператору.
- Повторне повідомлення чітко каже, коли викликати обслуговування.
- `ignore_after_command_ms` перекриває лише перехідний апаратний reset входів і не скидає repeat-логіку через хибний OK стан.
- Tray-іконка та tray-меню відповідають реальному стану.
- Перезавантаження конфігурації також завантажує змінені мови.
- Журнал читабельний.
