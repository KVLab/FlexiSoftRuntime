# FlexiSoft Runtime

FlexiSoft Runtime — це допоміжна сервісна програма для SICK Flexi Soft. Вона була створена, щоб зменшити повторні непотрібні виклики обслуговування на трубозгинальному верстаті CRIPPA, де часто потрібно лише скинути стан після неправильно закритого або механічно зношеного кожуха / саркофага.

Мета не в тому, щоб замінити обслуговування у випадку справжньої несправності. Мета — відфільтрувати типову помилку оператора: оператор неправильно закриває кожух, Flexi Soft утримує стан помилки, і обслуговування викликають лише для виконання reset. Runtime зрозуміло повідомляє оператору, що потрібно перевірити, і дозволяє запустити заздалегідь підготовлений імпульс reset.

**FlexiSoft Runtime не є частиною функції безпеки машини.** Це лише допоміжне програмне забезпечення для оператора. Безпечне оцінювання, безпечний стан машини та дозвіл / reset логіки безпеки завжди мають забезпечуватися проєктом Flexi Soft і проводкою машини.

---

## Для чого використовується

Типовий випадок використання:

1. Оператор закриває кожух / саркофаг машини.
2. Через зношення, неправильне закриття або несинхронне спрацювання датчиків у Flexi Soft залишається активна помилка.
3. Runtime показує повідомлення з чіткою інструкцією для оператора.
4. Оператор перевіряє кожух і підтверджує імпульс reset.
5. Runtime записує налаштований RS-232 command bit через RK512.
6. Проєкт Flexi Soft створює з цього біта короткий імпульс reset.
7. Якщо та сама помилка повторюється, Runtime показує повторне повідомлення, а оператор має викликати обслуговування або виконати фізичну перевірку.

Runtime насамперед вирішує повторювані, прості, але неприємні для експлуатації ситуації, коли машина механічно не закрита правильно, але втручання обслуговування потрібне лише для виконання reset.

---

## Що робить програма

- читає вибрані стани з Flexi Soft через RK512,
- показує оператору повідомлення про помилки,
- дозволяє підтвердити імпульс reset,
- відстежує повторне повернення тієї самої помилки,
- при повторній помилці показує більш виразне повторне повідомлення,
- дозволяє ручний command з tray-меню,
- підтримує багатомовний інтерфейс і локалізовану документацію,
- записує власний сервісний журнал програми.

Runtime **не журналює події машини як виробничий або безпековий реєстратор**. Він журналює власні події: запуск, завантаження конфігурації, стан комунікації, показані повідомлення, команди, reconnect, shutdown та подібну сервісну інформацію.

## Комунікація з Flexi Soft

Runtime спілкується з Flexi Soft через RK512.

Підтримувані способи підключення:

| Спосіб | Використання |
| --- | --- |
| Прямий COM / RS-232 | Runtime працює на ПК, який має фізичний або віртуальний послідовний порт, підключений до Flexi Soft. |
| TCP через Ethernet/RS-232 перетворювач | Runtime працює на ПК машини та підключається до Flexi Soft CPU через наявну мережеву інфраструктуру машини. |

Для інтеграції в наявну машину зазвичай практично використати Ethernet/RS-232 перетворювач. Runtime тоді може працювати безпосередньо на OP/PC машини, часто навіть на старішій системі Windows XP. Комунікація з Flexi Soft CPU може проходити через наявну мережу машини замість окремого довгого послідовного кабелю.

Так втручання в машину залишається мінімальним:

- Runtime працює на машинному PC/OP.
- Flexi Soft залишається головним блоком безпеки.
- Перетворювач лише передає RK512-комунікацію між runtime та RS-232 інтерфейсом Flexi Soft.
- Наявна мережева інфраструктура машини може використовуватись для зв’язку runtime ↔ перетворювач.

## Важливі файли для інтеграції та сервісу

Звичайний оператор з цими файлами не працює. Для інтеграції та сервісу важливі насамперед:

| Файл / папка | Значення |
| --- | --- |
| `conf/config.json` | Комунікація, контрольовані канали, тексти повідомлень, вихідні command-біти та правила повторного повідомлення. |
| `conf/languages.json` | Переклади інтерфейсу та додаткові шрифти. |
| `conf/runtime_state.json` | Останні runtime-вибори користувача, наразі головно вибрана мова. |
| `FlexiSoftMdReader.exe` | Зовнішній переглядач документації, який використовує Runtime. |
| `fonts/` | Додаткові шрифти для мов, для яких у системі може не бути відповідного шрифту. |
| `docs/` | Локалізована документація. |
| `flexi_runtime.log` | Сервісний журнал програми. |

Метадані About під час build вбудовуються безпосередньо в `FlexiSoftRuntime.exe` з `src/about.h`; вони не зберігаються в окремому runtime-конфігураційному файлі. Вбудовані дані About містять інформацію про продукт/версію/build і локалізовані описи для EN/CZ/UK/FR/DE.

## Багатомовний інтерфейс

Мова за замовчуванням — англійська. Інші мови додаються в `conf/languages.json`.

Runtime не обмежений фіксованим набором мов. Якщо додати переклади й, за потреби, документацію, можна додати іншу мову.

Документація відкривається відповідно до активної мови, якщо існує відповідний файл:

```text
docs/README_<мова>.md
docs/MANUAL_<мова>.md
```

Якщо локалізована документація відсутня, використовується базова документація без мовного суфікса.

## Налаштування у Flexi Soft Designer

### Увімкнення RS-232 routing для CPU

У проєкті Flexi Soft має бути увімкнено:

```text
Увімкнути RS-232 routing для CPU
```

![Налаштування RS-232 routing для CPU](assets/flexisoft_designer_rs232_routing.png)

Без цього налаштування RS-232 сигнали можуть бути недоступні для логіки CPU.

### Імпульс reset з RS-232 біта

Runtime лише записує RS-232 command bit. Сам імпульс reset має створюватися в логіці Flexi Soft CPU.

Рекомендований принцип:

```text
RS-232 bit -> виявлення фронту -> таймер / короткий імпульс -> reset-реле або reset-вихід
```

Приклад:

```text
RS232 0.0 -> виявлення фронту -> таймер затримки вимкнення -> XTIO[1].Q1
RS232 0.1 -> виявлення фронту -> таймер затримки вимкнення -> XTIO[1].Q2
```

![Приклад reset-реле з RS-232 бітів](assets/flexisoft_designer_rs232_reset_relays.png)

Така логіка рекомендована через безпечну поведінку при помилці комунікації. Якщо під час command зникне зв’язок або runtime перестане працювати, контрольовані входи не повинні залишитися статично відключеними, а reset-сигнал не повинен залишитися постійно активним. Тому короткий імпульс має забезпечувати проєкт Flexi Soft, а не лише runtime.

Конфігурація в `conf/config.json` має відповідати тому, як RS-232 command-біти використані в проєкті Flexi Soft.

## Повідомлення

Runtime показує повідомлення відповідно до налаштованих каналів.

Звичайне повідомлення каже оператору, що потрібно перевірити, наприклад:

```text
Перевір, чи саркофаг повністю закритий.
Відкрий і знову правильно закрий кожух.
Після перевірки підтвердь reset.
```

Оператор зазвичай має два варіанти:

| Вибір | Значення |
| --- | --- |
| Так / YES | Після перевірки запускає імпульс reset. |
| Ні / NO | Закриває повідомлення без імпульсу reset. |

Тексти повідомлень задаються в конфігурації.

---

## Повторне повідомлення

Повторне повідомлення показується, якщо та сама помилка повторно повертається після імпульсу reset.

Це важливо насамперед для механічно зношеного кожуха / саркофага:

- одноразова помилка може означати лише неправильне закриття,
- повторна помилка означає, що потрібно перевірити кожух, датчик або проводку,
- оператор не повинен нескінченно підтверджувати reset без перевірки причини.

Приклад змісту повторного повідомлення:

```text
Помилка повторно повертається.
Перевір правильне закриття кожуха та стан датчика.
Якщо повідомлення повторюється, виклич обслуговування.
```

## Tray-іконка та стан каналів

Runtime працює в області сповіщень Windows. Колір tray-іконки швидко показує загальний стан програми та комунікації.

| Стан іконки | Значення |
| --- | --- |
| Зелена | Комунікація з Flexi Soft CPU справна, і жоден контрольований канал не в помилці. |
| Червона | Комунікація справна, але принаймні один контрольований канал повідомляє помилку. |
| Жовта / нейтральна | Програма працює, але комунікація або стан CPU ще не повністю підтверджені. Типово під час запуску, reconnect або очікування відповіді. |
| Сіра / помилка комунікації | Runtime не має дійсного з’єднання з Flexi Soft CPU або комунікація в помилці. |

Tray-меню також показує стан контрольованих каналів CH1–CH4. Для кожного увімкненого каналу видно його назву та стан, наприклад чи канал активний/неактивний і чи він OK або в помилці.

Завдяки цьому оператору не потрібно одразу відкривати діагностику Flexi Soft. У tray-меню швидко видно, який контрольований вхід проблемний.

## Ручний command з tray-меню

Tray-меню може містити ручний command для окремих каналів.

Ручний command доступний лише тоді, коли комунікація з Flexi Soft CPU дійсна. Якщо комунікація несправна, пункти command неактивні.

---

## Перезавантаження конфігурації, reconnect і завершення

У tray-меню можна перезавантажити конфігурацію. При цьому знову завантажується не лише `conf/config.json`, але й мовні файли та runtime-налаштування мови. Це корисно при зміні текстів повідомлень, перекладів або комунікаційних параметрів без ручного перезапуску програми.

Якщо під час перезавантаження конфігурації відкрите повідомлення, runtime його закриє. Якщо помилка все ще триває, після перезавантаження буде показано нове актуальне повідомлення за новою конфігурацією та новими текстами.

Метадані About є частиною EXE і не змінюються під час перезавантаження конфігурації.

У tray-меню також можна вручну запустити reconnect комунікації. Це використовується при проблемі з перетворювачем, мережевим з’єднанням або CPU.

Завершення програми виконується з tray-меню. Під час завершення runtime записує власний shutdown-запис у журнал.

## Журнал

Типовий журнал:

```text
flexi_runtime.log
```

Журнал є сервісним записом самої програми. Він завжди англійською незалежно від мови інтерфейсу.

Журнал містить, наприклад:

- запуск програми,
- завантаження конфігурації,
- стан комунікації,
- втрату та відновлення комунікації,
- command ON/OFF,
- повторне повідомлення,
- ручний reconnect,
- shutdown.

Журнал не замінює діагностику безпеки Flexi Soft і не є виробничим журналом машини.

## Документація

Програма може відкривати мовно локалізовану документацію.

Базові назви:

```text
docs/README.md
docs/MANUAL.md
```

Локалізовані назви:

```text
docs/README_cz.md
docs/MANUAL_cz.md
docs/README_uk.md
docs/MANUAL_uk.md
docs/README_fr.md
docs/MANUAL_fr.md
docs/README_de.md
docs/MANUAL_de.md
```

Суфікс має відповідати коду мови в `languages.json`.

Документація зазвичай відкривається через `FlexiSoftMdReader.exe` (v1.0.1 в актуальному пакеті Runtime). Runtime передає Reader документ і фактичний шрифт UI. Reader v1.0.1 містить сумісну обробку для старого IE engine у Windows XP. Якщо Reader неможливо використати, runtime переходить до Notepad, а потім до ShellExecute.

## Базова перевірка після впровадження

Після впровадження перевір:

- RS-232 routing для CPU увімкнено у Flexi Soft Designer.
- RS-232 command-біти підключені в логіці Flexi Soft.
- Імпульс reset створюється в логіці Flexi Soft як короткий імпульс.
- Runtime підключається до комунікації.
- Колір tray-іконки відповідає реальному стану комунікації та каналів.
- Стан контрольованих каналів у tray-меню відповідає реальному стану Flexi Soft.
- Повідомлення відповідають реальним станам машини.
- Reset command записує правильний біт.
- Перезавантаження конфігурації також завантажує змінені переклади та мовні файли.
- Повторне повідомлення з’являється при повторному поверненні тієї самої помилки.
